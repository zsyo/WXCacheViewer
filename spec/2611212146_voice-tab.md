# 语音（voice2）

## 背景

前五个标签页已经覆盖视频号、聊天视频、表情、图片与聊天文件。聊天里的语音消息一直没做，
原因是 `voice2` 下的文件后缀写着 `.amr`，内容却是 SILK v3，系统播放器、普通解码库都打不开。
这一版引入 SILK 解码库，做「能列、能听、能导出」。

## 设备实测

真机上 `MicroMsg/<hash>/voice2` 是两级十六进制目录：

```
voice2/
├── 03/
│   └── fa/
│       └── msg_amr_<26 位十六进制>.amr     20040 B
├── 05/2e/msg_amr_<...>.amr                 47674 B
└── ...
```

- 一级目录 30 多个，与 `image2` 同量级但小得多；单个文件从 2 KB 到 500 KB 不等。
- 文件名统一为 `msg_amr_` + 26 位十六进制 + `.amr`。
- 文件头是 `02 23 21 53 49 4C 4B 5F 56 33`，即 `0x02` + `#!SILK_V3`；正常情况下标准 SILK
  应以 `#!SILK_V3` 开头、以 `0xFF 0xFF` 结尾，微信插了一个私有字节并去掉了结尾标记。
- 目录里有不少二级目录是空的：语音被微信清理过之后只剩空壳，这属于正常现象。

（文件名与体积均为示例值，不是真机上的实际数据。）

## 设计

### 缓存源

`SourceRegistry.VOICE`：`MicroMsg/<hash>/voice2`，递归源，`maxDepth = 3`，
`findNames = ["*.amr"]`，`pageSize` 沿用默认值，`allowDelete = false`，`typeHint = SILK`。

路径白名单：

```kotlin
Regex("^(?:[0-9a-f]{2}/){1,2}msg_amr_[0-9a-f]{8,40}\\.amr$")
```

允许一级与两级十六进制目录（个别版本只有一级），限制前缀与扩展名，避免把目录里的其它东西列出来。
与图片、朋友圈一样按一级子目录分页，一页只 `find` 一个 `xx/`。

### 格式识别

`domain/VoiceFormat` 负责纯字节判断，便于单测：

- `kindOf(bytes)` 区分标准 SILK、微信封装 SILK、真 AMR、未知（只认前 10 个字节）。
- `toStandardSilk(bytes)` 只在微信封装时剥掉首字节 0x02，标准格式原样返回，AMR/未知抛异常。
- `durationMillisOfStandardSilk(bytes)` 按帧头（2 字节小端长度）数帧，每帧 20ms 估算总时长。

`FileTypeDetector` 也补了 SILK / AMR 两种魔数，避免以后哪天真机出现真 AMR 时被认成未知。

### 解码与播放

依赖 `com.github.xxinPro:SilkDecoder:1.0`（jitpack，自带 arm64-v8a / armeabi-v7a / x86 / x86_64
四个 ABI 的 `libdecoder.so`），公开 API 是 `decodeToWav` / `decodeToPcm` / `decodeToMp3`。
该库自带的 appcompat 与 material 依赖对解码没有用，构建时排除掉。

`data/audio/VoicePreparer` 的流程：

1. root 把原始文件复制到 `cacheDir/voice_raw/<sha1(key#size) 前 16 位>.amr`；
2. 读前 10 字节判断格式，是 AMR 就直接返回原文件，是 SILK 就剥掉私有头写成 `.silk`；
3. 调用 `decodeToWav(..., 24000)` 解到 `cacheDir/voice_decoded/<id>.wav`；
4. 用期望时长校验解码结果（见下），通过后把采样率写进 `<id>.rate` 旁注文件。

**采样率兜底**：微信早期版本录音是 16kHz、新版 24kHz，SILK 头里没有采样率字段。按 24kHz 解码后
用「帧数 × 20ms」的期望时长比对 wav 的实际时长，偏差超过 15% 说明解码器没有按 API 采样率重采样，
改按 16kHz 再解一次。`.rate` 旁注让后续播放直接复用，不必每次重算。

解码器是原生库，不保证线程安全，所有解码走同一个 `Mutex`；失败（含 `UnsatisfiedLinkError`）
统一抛成「语音解码失败」，由界面提示，不会静默播放噪声。库的布尔返回值在成功/失败上并不可靠，
判断依据是产物文件是否大于 44 字节（wav 头）。

播放用独立的 `VoicePlayer`（ExoPlayer，音频属性声明为 `USAGE_MEDIA` + `SPEECH`，拔耳机自动暂停），
不进入全屏播放页——语音通常只有几秒，列表内联播放更顺手。

### 界面

「语音」标签页放在「文件」之前，固定单列列表（`SourceTab.listOnly`）：

```
( ▶ )  10-19 19:01
       语音 / 47.7 KB / 00:12
       ──────────────           ← 播放中显示进度
```

- 左侧圆形按钮：解码中显示环形进度，其余显示播放/暂停图标。
- 标题用修改时间——文件名是 `msg_amr_<hex>`，对人没有意义。
- 播放到结尾时进度停在末端，再点一次从头播放；切换标签页或账号会停止播放。
- 语音属于聊天记录，`allowDelete = false`，工具条不显示删除；仍可长按多选导出。

### 导出

`ExportKind.MUSIC` → `Music/WXCacheViewer/`，文件名沿用
`wxvoice_<年月日_时分秒>_<相对路径哈希 8 位>.mp3`，重名时加 `(1)`、`(2)`。

SILK 先解码成 mp3（24kHz / 64kbps 单声道）再落盘：应用自己写不了公共目录，解码产物先放在私有目录，
再由 root `cp` 到目标位置（新增 `WxPaths.exportLocalFileCommand`）。真 AMR 则原样导出 `.amr`，
MIME 跟着实际扩展名走。

`domain/ExportNaming` 把原来写在 `CacheRepository` 里的「命名 + 重名加序号」提出来，语音与其它源共用。

## 验证

- `VoiceFormatTest`：三种格式的识别、剥头只掉一个字节、AMR/未知拒绝、按帧数算时长（含 `0xFF 0xFF` 结尾）。
- `FileTypeDetectorTest`：`02 + #!SILK_V3`、纯 `#!SILK_V3`、`#!AMR` 的魔数。
- `SourceRegistryTest`：一级/两级目录可接受、非十六进制目录与非法扩展名被拒、语音页只读且排在文件页之前。
- `WxPathsTest`：语音分页命令 `find -maxdepth 2 -name '*.amr'`、导出本地文件的命令形态。
- `ExportNamingTest`：语音命名稳定性、聊天文件保留原名并可加序号。
- `testDebugUnitTest` 全部通过；`lintDebug`、`assembleDebug`、`assembleRelease` 通过，
  release 包中确认 `libdecoder.so`（四个 ABI）与 `xyz.xxin.silkdecoder` 的类都在（R8 加 keep 规则）。

## 范围外

- 语音与消息、发送人的对应关系要读加密的 `EnMicroMsg.db`，不在本次范围内；列表只能按时间展示。
- 不支持把语音转文字。
- 微信清理过的语音无法恢复，空目录就是空目录。
