# 权限：没有 root 时的引导页

## 需求

之前没有 root（或 su 授权被拒绝）时，账号页会显示一句「未检测到 root 权限」加一个「重试」按钮，
下面直接铺着 `diagnostics` 全文 —— 十几条 shell 命令的 stdout/stderr，等宽字体、限高滚动。
用户看到的是「一堆错误代码」，既不知道卡在哪一步，也不知道接下来该干什么。

现在改成引导页：说清**为什么**读不到微信缓存、**卡在哪一步**、**具体怎么补救**，
诊断信息收进折叠区，只有真要排查时才展开。

顺带解决一个体验问题：原来无 root 时要先把整套诊断跑完（su 不存在时二十来条命令，
被拒绝时每条都可能等超时）才更新界面，期间一直显示「正在读取账号…」。

## 调研结论：为什么不做 Shizuku 支持

最初的设想是「没 root 的用户用 Shizuku 也能读微信缓存」，查证后不成立，因此**不引入 Shizuku**：

- 微信缓存在 `/data/user/0/com.tencent.mm`，是该应用的私有目录（0700，属微信 uid）。
- Shizuku 以 ADB / 无线调试方式启动时，执行体是 **shell 身份（uid 2000）**。官方 README 原文：
  「For example, Shell (ADB) cannot access other apps' data files `/data/user/0/<package>`」。
- 只有以 **root 方式**启动 Shizuku（`Shizuku.getUid() == 0`）时才有 root 能力 —— 而这条路径的前提
  本身就是设备已经 root，与「给没 root 的用户用」的目标相悖。
- Dhizuku（设备所有者）模式同样不是文件系统层面的 root，读不了该目录。

结论：Shizuku 在这个应用里只能当「su 的替代通道」，无法替代 root 本身。既然目标用户是有 root 的人，
它带来的收益（少几次 su 调用）不足以抵掉新增依赖、清单项与一套授权流程，故不做。

## 引导页结构

`ui/common/PermissionGuideScreen`，整页可滚动，内容自上而下：

1. 锁图标 + 标题「需要 root 权限」；
2. 固定说明：缓存位于应用私有目录、Android 只允许 root 读，**并且明说这不是「漏给了某个权限」**，
   免得用户反复找「权限开关」；
3. 按失败原因分支的一段「怎么办」（tonal 卡片）；
4. 仅 `NO_SU` 时出现的「大致步骤」卡片（解锁 BL → 刷入 Magisk/KernelSU/APatch → 回来自检）；
5. 主按钮「重新检测」；
6. 仅 `NO_SU` 时的「了解 Magisk」文字按钮（跳系统浏览器打开官方仓库）；
7. 「查看诊断信息」折叠区；
8. 收尾一句：没有 root 就读不到，没法靠其它权限或工具绕过。

不做「跳到 root 管理器」的深链：Magisk / KernelSU / APatch 的包名和入口各不相同，猜错就是一次
打不开的跳转，不如把该点哪里写清楚。打开 Magisk 仓库走系统浏览器，应用自身仍然不联网。

## 按原因分支

| Reason | 含义 | 引导重点 |
|---|---|---|
| `NO_SU` | 没有 su 二进制 | 设备还没 root，给三步走 + Magisk 入口 |
| `DENIED` | su 拒绝或返回非 0 | 已在 root 管理器的超级用户列表里被拒，改成允许后重测 |
| `TIMEOUT` | 等 su 返回超时 | 授权弹窗可能被系统「后台弹出界面」限制拦下 |
| `UNKNOWN` | 其它 | 先确认已 root 且已允许，再看诊断 |

## 诊断的降级与时机

- **先显示引导页，再收集诊断**：`AccountViewModel` 在 `root is Unavailable` 时先 `loading = false`
  并写入 `rootState`，随后才 `collect` 诊断并回填。界面不再卡在加载态。
- **按能力降级**：`RootDiagnostics.collect(..., privileged)`。
  `NO_SU` 与 `TIMEOUT` 传 `false` —— 前者跑 shell 探测全是「命令不存在」，后者每条都要再等一轮超时，
  两者都只有空白没有信息；此时只记录 SDK、机型、ABI，以及应用自己能否看到 `/data/user/0/com.tencent.mm`，
  这几行恰恰是判断「是不是真没 root」的关键。`DENIED` / `UNKNOWN` 传 `true`，保留完整探测。
- 无特权时不再把 `diagnostics.txt` 复制到 `/sdcard/MT2/mcp`（那一步也要 su），只写应用私有目录。

## 实现

- `ui/common/PermissionGuideScreen.kt`：引导页本体，`rememberSaveable` 记住诊断折叠状态。
- `ui/account/AccountSelectScreen.kt`：`RootState.Unavailable` 分支从 `ErrorView` 换成引导页，
  删掉原 `rootErrorMessage()`。
- `data/root/RootDiagnostics.kt`：新增 `privileged` 参数与 `publish(share)`。
- `viewmodel/AccountViewModel.kt`：先出界面再收诊断。
- `ui/common/FileOpener.kt`：新增公共 `openUrl()`，设置页原有的私有实现改为复用（避免两份）。
- `strings.xml`：新增 `root_guide_*` 一组，删除已无引用的 `root_error_*`。
