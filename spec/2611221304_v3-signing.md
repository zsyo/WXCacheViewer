# 正式包启用 v3 签名

时间：2026-11-22 13:04

## 背景

此前四个正式包只有 v2 签名（v1/v3/v3.1/v4 均为 false），这与 minSdk 24 + AGP 默认行为一致。项目走 GitHub Release 直接分发、不上架商店，v2 本身够用；但 v3 在 v2 基础上附带密钥轮换谱系（proof-of-rotation），启用后日后再换签名密钥时老用户仍能正常升级，不必先卸载。成本仅为签名块多一小段数据，无运行时影响，因此决定启用。

## 改动

在 `app/build.gradle.kts` 的 `signingConfigs.release` 增加：

```kotlin
enableV2Signing = true
enableV3Signing = true
```

- `enableV2Signing` 显式写出（原本 AGP 默认就开启），与 v3 并列以便一眼看清启用的方案。
- v1 不启用：仅面向 Android 6 及以下，minSdk 24 用不到。
- v4 不启用：仅 `adb install --incremental` 增量安装需要，且会额外产出 `.idsig` 文件，本项目分发场景不需要。
- AGP 9 的开关是 `Property<Boolean>`（`enableV3Signing`），Kotlin DSL 中可直接赋值；已通过本地 gradle-api 9.5.0 的 `SigningConfigImpl` 确认属性存在。

## 关键点：证书不变

签名方案变化只改签名块结构，不改签名密钥。启用前后证书指纹必须完全一致，否则老用户无法覆盖升级：

- SHA-256: `628af241a34e133abedb6d928a3456e999f2b3020563b08283211b68794e3e89`
- SHA-1: `42c1440db2bc371abf134dd63aeedb506c78ddd9`
- DN: `CN=zsyo, O=WXCacheViewer, C=CN`

实测启用 v3 后指纹与 GitHub Release v0.1.0、升级前本地 release 包三者一致。

## 连带确认

- CI 的 Verify signature 步骤用 `apksigner verify --print-certs` 打印签名信息（不做方案数量断言），v3 启用后输出变为 `V3.0 Signer: ...`，校验步骤照常通过。
- `zipalign -c -P 16` 仍需通过：AGP 的签名在对齐之后进行，加 v3 不影响 16KB 页对齐。

## 验证

- 80 个单测、`lintDebug`、`assembleDebug`、`assembleRelease` 全部通过，零警告零错误。
- 四个 ABI 正式包均为 `v2 scheme: true`、`v3 scheme: true`，`v1`/`v4` 为 false。
- 四包证书 DN 与 SHA-256/SHA-1 指纹与启用前一致。
- 四包 `zipalign -c -P 16` 校验全部通过。
