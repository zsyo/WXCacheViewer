# 播放音量改为应用内独立控制

## 背景

原音量控制通过 `AudioManager.setStreamVolume(STREAM_MUSIC, ...)` 直接改**系统媒体音量**，带来两个问题：

1. 调播放器音量会改动整机媒体音量，退出播放器后其他应用的声音也被改变，属于越界副作用。
2. 音量档位受系统流音量档数限制（常见 15 档），且与系统音量面板共用状态，无法做到只影响本应用。

## 目标

音量只在播放器内部生效，与系统媒体音量解耦；拖动 / 点按手感与此前一致。

## 实现

- `SimpleVideoPlayer` 新增 `setVolume(Float)`，内部写入 ExoPlayer 的 `player.volume`（0f..1f）。播放器音量是解码输出端的增益系数，硬件音量仍由系统单独控制，二者相乘。
- `PlayerScreen` 删除 `AudioManager` 相关代码（`audioManager`、`maxVolume`、`STREAM_MUSIC`）。
  - 音量状态由 `Int`（系统档位）改为 `Float`（0f..1f）。
  - `changeVolume` 直接调用播放器音量接口并更新状态，不再读写系统流音量。
- `SettingsRepository` 新增 `playbackVolume`（SharedPreferences，`playback_volume`），进入播放页时读取并应用，退出后保留。
  - 拖动过程中只更新内存与播放器，选择结束（`onDragEnd` / `onDragCancel` / 点按）才落盘，避免每帧写 SharedPreferences。
- 垂直音量条与百分比按 0f..1f 换算，显示为整数百分比；音量为 0 时音量图标半透明表示静音。

## 验证

- `assembleDebug`、`testDebugUnitTest`、`lintDebug` 全部通过。
- APK 经 MT 安装到设备。
- 需真机确认：拖动垂直音量条时系统音量面板不应弹出、系统音量不变；退出重进播放页应保持上次的应用内音量。
