# 播放页：顶栏对齐图片预览，支持导出与长按复制

## 需求

播放页顶栏此前只有一个「返回 + 文件名」，而图片预览页是「返回 + 文件名（长按复制）+ 导出」。
两页都是整屏查看，样式不统一会显得像两套界面；更要紧的是播放页没有导出入口——
看中一个视频还得退出去多选，路径太长。

## 交互

- 顶栏右侧新增导出按钮，与图片预览页同一个图标、同一个回调（`GalleryViewModel.exportOne`）：
  导出到设置里的导出目录下「视频」子目录，再由 `MediaScannerConnection` 通知系统媒体库。
- 文件名长按复制，复制后底部弹「已复制文件名」。
- 点文件名与点画面行为一致（切换控制层显隐），不在顶栏中间留一块点不动的死角。
- 横屏按钮不放在顶栏，改为画面右侧悬浮（见 `spec/2611251635_player-landscape.md`）。

## 顶栏要自己接管手势

第一版只给文件名加了 `combinedClickable`，结果真机上长按标题复制时会顺带触发左右快进/快退。

原因：顶栏 `Row` 本身没有任何 `pointerInput`。Compose 的命中测试里，一个节点只有挂了
pointer input 才会被算作命中；顶栏空白处（标题两侧、内边距）没有子节点接管时，事件直接落到
下一层的全屏手势层，于是「长按」被解释成连续快退/快进。

修法：给顶栏 `Row` 挂一个 `detectTapGestures`，`onTap` 照旧切换控制层，`onLongPress` 空实现。
这样顶栏在命中测试里占住自己的区域，事件不再穿透；标题自己的 `combinedClickable` 先消费按下事件，
父级 `detectTapGestures` 的 `awaitFirstDown(requireUnconsumed = true)` 便会跳过，不会双触发。

## 验证

- `lintDebug` 无告警，四 ABI `assembleDebug` 通过，单测 151 条全绿。
- 真机：长按标题只弹「已复制文件名」，不再出现快进/快退；点顶栏空白处仍能切换控制层；
  导出视频落到「视频」子目录且能在相册里看到。
