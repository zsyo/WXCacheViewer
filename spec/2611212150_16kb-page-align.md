# 消除 16KB 页兼容性弹窗

## 现象

Android 16（16KB 页）设备上每次冷启动都弹「Android 应用兼容性」对话框，内容为：

```
此应用不符合 16 KB 对齐要求。ELF 文件对齐检查失败。
以下库未进行 16 KB 对齐：
· lib/arm64-v8a/libandroidx.graphics.path.so：未知错误
· lib/arm64-v8a/libdecoder.so：LOAD 区段未对齐
```

对话框由系统在启动 debuggable 应用时给出，不是应用自己弹的，因此没有开关能直接关掉。

## 原因

16KB 页设备要求 `.so` 的每个 LOAD 段 `p_align >= 0x4000`。逐段读 ELF program header：

| 库 | LOAD 段 p_align | 结论 |
| --- | --- | --- |
| `libandroidx.graphics.path.so` | `0x4000` | 已对齐（graphics-path 1.0.1） |
| `libdecoder.so`（SILK 解码） | `0x1000` | 未对齐，jitpack 上是 2019 年编的预编译包 |

`libdecoder.so` 来自 `com.github.xxinPro:SilkDecoder:1.0`，作者只发布了预编译 so，仓库里没有编译脚本，也没有更新版本，无法指望上游重编。APK 的 zip 对齐没有问题（`zipalign -c -P 16` 通过），问题只在 ELF 段本身。

## 方案

把 SILK v3 解码器与 LAME 的 C 源码纳入模块自己编译，替换第三方 aar：

- `app/src/main/cpp/libsilk/`：Skype SILK v3 定点解码器（110 个 .c）。
- `app/src/main/cpp/libmp3lame/`：LAME，导出 mp3 用。
- `app/src/main/cpp/silk_decoder.c`：SILK 解包成 PCM 的实现。
- `app/src/main/cpp/silk_jni.c`：只保留两个入口——`decodeToWav`（写 16bit 单声道 wav 头）与 `decodeToMp3`（PCM 交给 LAME 编码）。
- `app/src/main/cpp/CMakeLists.txt`：`-Wl,-z,max-page-size=16384` 显式对齐；NDK r28 默认也是 16KB。

Kotlin 侧新增 `data/audio/SilkCodec`（`System.loadLibrary("wxsilk")` + 两个 external 方法），`VoicePreparer` 改为调用它，返回值 0 视为成功。jitpack 仓库、`silk-decoder` 依赖与对应的 keep 规则一并删除，换成 keep 我们自己的 `SilkCodec`（JNI 按「包名_类名_方法名」查入口，混淆后找不到）。

顺带修掉上游源码里的两个未初始化变量：`loss_prob`（丢包模拟的概率，未初始化时取值不确定，可能把整段语音丢空）与 `quiet`；输入路径缓冲从 150 字节放宽到 1024，避免长路径越界。

## 代价

- 构建需要 NDK `28.2.13676358` 与 CMake `3.22.1`（`app/build.gradle.kts` 已声明，SDK 里缺会自动报错提示安装）。
- 首次编译要编约 150 个 C 文件 × 4 个 ABI，增量构建不受影响。
- 不再依赖 jitpack，离线构建更容易。

## 验证

1. 四个 ABI 的 `libwxsilk.so` 每个 LOAD 段 `p_align` 都是 `0x4000`。
2. `zipalign -c -P 16 -v 4 app-debug.apk` 通过。
3. 装机后冷启动不再出现兼容性对话框。
4. 语音页播放语速音调正常，导出 mp3 可播放。
