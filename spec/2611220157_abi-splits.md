# 按 ABI 拆分 APK

## 背景

此前未配置 ABI 拆分，Gradle 默认把所有 ABI 的原生库打进一个通用 APK。用户看到只产出一个文件，与常见 Android 项目产出多个架构包不一致。

核对发现：CMake 实际编译出四个 ABI（arm64-v8a、armeabi-v7a、x86、x86_64），但 AGP 默认只打包前三个——通用 APK 里缺少 x86_64 的 `libwxsilk.so`，x86_64 设备安装后语音功能会崩溃。拆包时一并修正。

## 改动

`app/build.gradle.kts`：

- `splits.abi`：开启拆分，`include` 四个 ABI（arm64-v8a、armeabi-v7a、x86、x86_64），`isUniversalApk = false`，不生成通用包，避免分发时多出一个混淆项。
- `androidComponents.onVariants`：用新 Variant API（AGP 9 已移除旧 `applicationVariants`）为每个输出分配独立 versionCode，规则是 `ABI 序号 * 10000 + 基础版本号`。序号：armeabi-v7a=1、arm64-v8a=2、x86=3、x86_64=4。基础版本号来自 `defaultConfig.versionCode`（CI 打 tag 时注入 run number）。这样四个包的 versionCode 互不冲突，避免安装器/商店互相判定为旧版本。

`.github/workflows/release.yml`：

- Verify signature：从校验单个 `app-release.apk` 改为遍历 `app-*-release.apk`，每个包都做 `apksigner verify` 与 `zipalign -c -P 16`。
- Rename artifacts：从 AGP 产物名 `app-<abi>-release.apk` 提取 ABI，统一命名为 `WXCacheViewer-<版本>-<abi>.apk`。
- Upload / Publish：artifact 与 Release 附件都覆盖全部四个包（glob `WXCacheViewer-*.apk`），不再写死单文件名到 `GITHUB_ENV`。

`README.md`：构建产物说明改为四个 ABI 包，附各架构适用设备表；Release 流程与取产物步骤同步改成多包。

## 产物与验证

四个 release 包，每个只含一套原生库（SILK + LAME 的 `libwxsilk.so` 与 `libandroidx.graphics.path.so`），体积约 2.9~3.0 MB，均小于原通用包（4.3 MB）：

| 包 | versionCode | so 数量 | 16KB 对齐 |
| --- | --- | --- | --- |
| app-armeabi-v7a-release.apk | 10001 | 2 | 通过 |
| app-arm64-v8a-release.apk | 20001 | 2 | 通过 |
| app-x86-release.apk | 30001 | 2 | 通过 |
| app-x86_64-release.apk | 40001 | 2 | 通过 |

`./gradlew :app:assembleRelease` 成功；CI 重命名脚本已在本机用 bash 模拟验证，四个产物名生成正确。
