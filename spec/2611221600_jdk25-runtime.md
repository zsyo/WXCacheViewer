# 升级运行环境到 JDK 25

## 背景
本机已安装 BellSoft Liberica JDK 25 LTS（`E:/Dev/LibericaJDK`），希望统一开发环境到 JDK 25，不再维护 JDK 21 的 GraalVM/JDK 路径。Gradle 9.9.2 官方支持运行 JDK 25；AGP 9.5.0 已修复 JDK 25 下 `generateReleaseRFile` 的告警。

## 方案
- `gradle.properties`：删除 `org.gradle.java.home`，运行 JDK 完全由 `JAVA_HOME` 决定；`org.gradle.jvmargs` 增加 `--enable-native-access=ALL-UNNAMED`，供 Gradle daemon 使用。
- `.github/workflows/release.yml`：`setup-java` 改为 Temurin 25；删除“Drop machine-specific JDK path”步骤；构建步骤增加 `GRADLE_OPTS=--enable-native-access=ALL-UNNAMED`，消除 JDK 25 下 Gradle launcher 访问 native-platform 的警告。
- `README.md`：构建环境改为 JDK 25，说明统一通过 `JAVA_HOME` 指定；CI 同步使用 JDK 25。
- 字节码目标本次保持不变（仍为 Java 17），与运行环境升级解耦。

## 验证
- `./gradlew --version`：Launcher JVM 与 Daemon JVM 均为 25.0.5 LTS。
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过。
- 设置 `GRADLE_OPTS=--enable-native-access=ALL-UNNAMED` 后，Gradle 输出不再出现 native access 警告。

## 回退
恢复 `gradle.properties` 里的 `org.gradle.java.home` 指向 JDK 21，CI 的 `java-version` 改回 21，并恢复删除的 sed 步骤。
