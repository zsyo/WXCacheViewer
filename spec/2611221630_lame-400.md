# 升级 vendored LAME 至 4.0

## 背景
vendored LAME 为 3.99.5（2012 年前后的版本）。上游 2026-07 发布 4.0，包含编译、缺陷与安全修复。项目只需要 JNI 里那组稳定的编码 API，不需要解码器部分。

## 方案
- `app/src/main/cpp/libmp3lame/`：用 LAME 4.0 稳定源码替换 3.99.5；同步替换 `app/src/main/cpp/include/lame.h`。
- `config.h`：不再为空。LAME 4.0 的 `config.h.in` 会为 `ieee754_float32_t` / `ieee754_float64_t` 做 typedef，移植版只保留这两个 typedef，其余 `HAVE_*` 由 CMake 编译参数提供。
- `CMakeLists.txt`：
  - LAME 源码从 `file(GLOB)` 改为显式清单，避免上游新增文件被误编；
  - 排除 `mpglib_interface.c`，它依赖未移植的 `mpglib/mpglib.h`，项目只做编码，不需要解码接口；
  - 增加 `-DHAVE_STDINT_H`，让 `machine.h` 显式引入 `stdint.h`。
- `README.md`：技术栈标注 LAME 4.0，许可证说明仍是 LGPL 2.0 及以后。

## 验证
- `:app:testDebugUnitTest :app:lintDebug :app:assembleRelease` 全过，四 ABI 原生库均编译成功。
- 用 vendored 4.0 源码在主机侧编译最小编码测试：16000 Hz 单声道、440 Hz 示例正弦波，输出 540 字节，帧同步头 `ff f3`，确认 MP3 编码链路可用。
- 四个 APK `apksigner verify` 与 `zipalign -c -P 16 4` 通过；`libwxsilk.so` 的 LOAD 段 `Align` 仍为 `0x4000`。

## 回退
恢复上一提交的 `libmp3lame/`、`include/lame.h` 与 `CMakeLists.txt`；保留 NDK/CMake/JDK 升级。若 4.0 在真机音频回归中出现问题，可先尝试同属 3.x 的 3.101 作为过渡。
