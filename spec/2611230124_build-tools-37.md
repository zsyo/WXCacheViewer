# 显式指定 build-tools 37.0.0

## 背景

`compileSdk = 37` 与 AGP 使用的 build-tools 版本没有绑定关系。AGP 9.5.2 的默认
`buildToolsVersion` 是 `36.0.0`，而 CI 和本地签名/对齐校验一直用的是
`build-tools/37.0.0` 里的 `apksigner`、`zipalign`，等于同一套产物链上并存两个 build-tools。

本地清理 SDK 时删掉 `build-tools;36.0.0` 后，构建日志出现：

```
Checking the license for package Android SDK Build-Tools 36 in ...
Installing Android SDK Build-Tools 36 in E:\Dev\Android\Sdk\build-tools\36.0.0
```

原因是 `android.builder.sdkDownload` 默认为 true，AGP 发现默认版本缺失就自动补装。
这属于隐式依赖：配置里看不到、清理时容易误删、CI 上也会多下载一次。

## 改动

`app/build.gradle.kts` 在 `compileSdk` 后显式声明：

```kotlin
buildToolsVersion = "37.0.0"
```

与其他工具链版本保持一致：

- `.github/workflows/release.yml` 的 `setup-android` 装的就是 `build-tools;37.0.0`
- 签名与 16KB 对齐校验从 `$ANDROID_HOME/build-tools/<最高版本>` 取 `apksigner` / `zipalign`
- `README.md` 的构建环境说明已写 Build-Tools 37.0.0，无需改动

## 影响

- AGP 编译改用 37.0.0，不再隐式依赖 36.0.0；CI 少一次 SDK 组件下载。
- `build-tools;36.0.0` 从此可以安全卸载，`35.0.0` 之前已确认可删。
- 版本号写死而非放进 `gradle/libs.versions.toml`，与 `compileSdk = 37` 的处理保持一致；
  升级 compileSdk 时要同步检查这一行。

## 验证

- `:app:testDebugUnitTest :app:lintDebug :app:assembleRelease` 全通过。
- 构建过程中不再出现 "Installing Android SDK Build-Tools 36"。
- 四个 ABI 的 release APK 签名校验与 `zipalign -c -P 16 4` 仍通过。
